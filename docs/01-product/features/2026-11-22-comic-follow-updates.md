# 漫画追更

## 1. 背景与目标

- 解决痛点：
  - `comic_favorite` 的 `has_update` / `latest_chapter` 两列无写入方，界面没有追更入口、没有巡检器、没有更新列表。
  - 旧 `local_favorite.db` 的"指定单个本地夹做追更"与桌面端现有收藏表双轨并存，会撕裂收藏账本，且覆盖不到网站账号里的网络收藏。
- 核心目标：
  - 建独立追更账本 `comic_follow`，与收藏解耦；本地收藏、网络收藏、未收藏漫画都能单独追更。
  - 详情页操作栏加「追更」开关，首次追更即以当前详情章节建基线。
  - 网络收藏页支持把当前网站收藏夹导入追更。
  - 单飞行低优先级串行巡检：同源节流、冷却跳过、单本重试、同源熔断、可中途取消。
  - 收藏页左侧书库面板加「追更」入口，更新置顶、未读红点、读后消红点。
- 非目标（Non-Goals）：
  - 不沿用 `local_favorite.db` 的"指定单个本地夹做追更"机制：与主表双轨，且覆盖不到网络收藏。
  - 不做应用关闭后的常驻进程 / 系统服务定时推送：桌面端无后台守护进程，资源与维护成本过高。
  - 首期不做检测到更新后自动静默下载：容易瞬时拉满带宽并触发站点封禁。
  - 不做高并发多源同时巡检：`EngineSession` 为串行共享实例，并发不仅撞盾，还会卡死前台浏览。
  - 不做网络收藏双向删除同步：防止接口异常把追更记录与已读水位清零，取消追更只由用户显式操作。
  - 不改动手机版分支 `D:\venera-compose`。

## 2. 用户操作流

1. 入口：漫画详情页顶部操作栏「收藏」旁的「追更」；收藏页左侧书库面板「追更」；网络收藏页顶栏「加入追更 / 同步追更」。
2. 过程：点击追更后写入 `comic_follow` 并以当前详情最新章节建基线（不标红）；在追更视图点「检查更新」按串行队列巡检，显示 `已完成 / 总数` 与当前源，可随时停止。
3. 结果：有新更新的条目置顶并显示「更新至：第 N 话（+M 话）」，左侧「追更」入口显示未读数；进入详情或读到最新话后自动清除该本红点。

## 3. 范围

- 涉及屏与路由：详情页操作栏、收藏 Hub 左侧书库、新增追更屏、网络收藏页、本地收藏卡片菜单。
- 涉及表与列（含迁移版本号）：`venera_core.db` v3 → v4；新增 `comic_follow`、`comic_follow_sync_source`，纯增量，不改旧表列。
- 涉及启动参数或构建项：无新增启动参数；设置页新增「启动时自动检查追更」与「冷却时长」。

## 4. 边界与异常

- 空态：追更列表为空时提示「还没有追更的漫画」并说明两个入口；「有更新」筛选为空时提示「暂时没有新更新」与上次检查时间。
- 加载中：检查按钮转为「停止检查」，显示已完成 / 总数与当前源；离开页面后台继续跑。
- 失败：单本失败写入 `last_error` 归入「异常」，不阻断其余条目；同源连续 3 次失败熔断该源剩余队列并提示过盾或重新登录。
- 能力缺失：源未安装 / 已停用 ⇒ 跳过并记错误；网站源未登录 ⇒ 导入按钮置灰并提示登录；`chapters` 为空 ⇒ 降级比对 `updateTime`；无网络 ⇒ 给出可读错误且不覆盖已有状态。
- 定时与备份：启动自动检查默认关闭，开启后只在开窗跑一轮、冷却期内条目跳过；`.venera` 归档带追更两表，老归档缺这两个 entry 时不覆盖本机追更。
