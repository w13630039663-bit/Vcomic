# 报错提醒系统重做与问题反馈集成（对接 GitHub Issue）

> 状态：已完成全部 `/grill-me` 需求对齐，待出 HTML 视觉方案稿并获批后实施。未获批不写码。

## 1. 背景与目标

- **解决痛点**：
  1. 现有报错弹窗（`DesktopErrorReport.kt`）为居中大白底卡片，在深色 UI 下对比突兀且遮挡主内容区；默认直接暴露线程名、代码行号与本地日志路径，普通用户难以理解。
  2. 软件内约 52 处运行期报错/告警仅写入后台日志，其中部分用户主动操作失败（如收藏失败、代理装配失败、缺少 VLC 起播失败）缺乏界面反馈。
  3. 缺乏便捷的软件内问题反馈与建议通道，用户遇到报错后难以一键整理环境信息与截图提交到 GitHub Issue。
- **核心目标**：
  1. 将报错提醒重做为**顶部胶囊通知栏 + 轻量下拉面板**，严格跟随当前深浅主题（暗色深炭半透明毛玻璃 + 细描边，亮色浅磨砂）。
  2. 按**「漫画 / 图库 / 系统」**三大类接入 14 处高价值隐藏报错 + 程序未捕获异常，实现“大白话标题 + 人话原因 + 分类标签”，技术栈与日志路径默认折叠。
  3. 在**顶栏最小化按钮左侧**增加常驻「问题反馈」入口，支持**「问题反馈」**与**「新功能建议」**双 Tab，双向打通报错记录复用，支持剪贴板/本地截图，并采用**零门槛 GitHub Issue 预填跳转**（自动复制截图到剪贴板 + 浏览器打开预填好标题/正文/标签的 Issue 页面）。
- **非目标（Non-Goals）**：
  1. **不接入高频资源兜底日志**（如 `D_图错 HTTP 403/404`、动图单帧解码错、单个画师头像失败、画廊标签词典降级）：刷图时每屏可能触发数十次，接入弹窗/胶囊会造成信息轰炸，继续留在后台日志。
  2. **不接管普通成功类轻提示**（如“已复制”）：继续保留现有轻 Toast，避免把正常操作混入错误记录。
  3. **不接入开发调试探针与后台定时清理**（如 `ProbeMain`、GPU 缓存校准、退出接线失败）：面向开发排查，不打扰用户。
  4. **不做应用内自动截取窗口画面**：截图仅支持「选择本地图片」+「Ctrl+V 粘贴剪贴板图片」。
  5. **不做软件内 GitHub OAuth 授权或自建中转后端**：避免在客户端引入复杂鉴权或维护图床服务，统一走浏览器 GitHub 新建 Issue 预填跳转 + 剪贴板带图。

## 2. 用户操作流

### A. 报错提醒流程
1. **平时无报错**：顶部胶囊通知栏**彻底隐藏**，不占用顶栏视觉空间。
2. **触发新报错**：
   - 顶部平滑滑出简短提示胶囊（带分类色点与大白话摘要）。
   - 数秒后自动缩回为带未读数字的小角标。
3. **查看与管理**：
   - 点击顶部角标/胶囊，向下展开轻量下拉面板（非全屏居中遮罩）。
   - 面板顶部提供**「全部 / 漫画 / 图库 / 系统」**筛选胶囊，以及「全部复制」「清空」操作。
   - 每条卡片默认展示：**大白话主标题 + 一行简短人话原因 + 分类小标签 + 时间/重复次数**；支持「详情」展开技术栈与日志路径、「复制」以及**「去反馈」**快捷按钮（一键带入该报错打开反馈面板）。
4. **退出/清空**：点击面板外部或关闭按钮收起下拉面板；点击「清空」后，顶部胶囊恢复彻底隐藏状态。

### B. 问题反馈与新功能建议流程
1. **入口**：顶栏最小化按钮左侧常驻轻量「反馈」图标按钮（跟随主题风格）。
2. **双 Tab 表单**：
   - **问题反馈 Tab**：填写标题/补充说明，支持直接**勾选/带入最近报错记录**（或粘贴其他信息），支持 **Ctrl+V 粘贴剪贴板图片** 或 **选择本地图片** 附带截图（可预览、删除）。
   - **新功能建议 Tab**：填写标题、功能介绍，同样支持 **Ctrl+V 粘贴** 或 **选择本地图片** 附带参考截图。
3. **提交到 GitHub Issue**：
   - 点击「前往 GitHub 提交」后，软件自动把**用户添加的截图（如有）写入系统剪贴板**并提示“截图已复制，请在打开的网页中 Ctrl+V 粘贴”。
   - 同时组装好 Issue 标题、正文（含系统版本、应用版本、所选报错详情与用户描述）以及对应标签（如 `bug` / `enhancement`），调用系统默认浏览器打开目标仓库的 `issues/new` 预填页面。

## 3. 范围与接入清单（共 14 处隐藏报错 + 未捕获异常 + 反馈模块）

- **涉及屏与模块**：
  - 桌面全局顶栏叠层（替换 `DesktopErrorReport.kt` 现有居中弹窗实现，并确保挂载于 `LocalChromePalette` 主题作用域内）。
  - 顶栏窗口控制区（在最小化按钮左侧加入常驻「反馈」入口按钮）。

  - GitHub Issue 仓库地址做成可配置常量（待主人提供最终目标仓库地址后填入）。

## 4. 边界与异常

- **空态**：面板打开但当前筛选分类下无记录时，显示对应分类的轻量空态文案；全部清空后自动收起并隐藏顶部角标。
- **高频重复报错**：同一错误短时间多次触发时，沿用计数合并（`×N`），不刷屏弹出多条胶囊。
- **主题切换**：亮/暗主题切换时，胶囊与下拉面板实时跟随 `LocalChromePalette` 与磨砂/描边令牌切换。

## 7. 实施复盘与教训（2026-11-22 真窗验收发现）

1. **未核对主题作用域边界（根因 1）**：`DesktopErrorToastOverlay()` 在 `VeneraDesktop.kt` 中挂载于 `VeneraDesktopApp(...)` 外部，而 `VeneraTheme` 仅包裹在 `VeneraDesktopApp` 内部。导致新做的胶囊、报错下拉面板与反馈面板全部运行在 Material3 默认浅色紫主题（`#ECE6F0` + `#6750A4`）中，未吃到暗色深炭主题与 `#0A84FF` 强调色。
   - **规矩沉淀**：以后改造任何全局浮层（Overlay / Dialog / Toast），动手前必须先向上核实挂载点外层是否实际包裹了 `VeneraTheme` 与 `LocalChromePalette`，禁止仅凭调用 `VeneraTokens.color` 臆断主题生效。
2. **HTML 方案稿的 CSS 磨砂与 Compose 渲染差异（根因 2）**：HTML 中使用 `backdrop-filter: blur(26px)` 配合 `0.78~0.84` 透明度，视觉上底层文字会被模糊；但 Compose 浮层没有逐区域实时高斯模糊，照搬低透明度会导致底层页面文字直接透出并形成重影。
   - **规矩沉淀**：Compose 浮层容器（下拉面板、反馈弹层）在无底层模糊遮罩时，表面不透明度必须保持高不透实底档（`≥ 0.96f` 或实色表面），仅保留 `1dp` 发丝描边与内嵌卡层次区分。
3. **图床 403 仍进入胶囊（范围漂移）**：原 `DesktopErrorBus.reportImageError` 仍在向胶囊推送 `HTTP 403` 图片加载失败，与计划“不接入高频图床 403 噪音”存在口径遗漏。
