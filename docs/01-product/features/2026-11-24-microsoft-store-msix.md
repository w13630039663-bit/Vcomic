# Microsoft Store 上架与 MSIX 双轨打包

> 2026-11-24 · 状态：规划草案（未来功能，待开发者账号与立项获批后实施；当前不写码）。

## 1. 背景与目标

- **解决痛点**：当前仅提供未签名的 `VComic-<版本>-setup.exe`（7z SFX）与 MSI 安装包，用户从网页下载安装会遇到浏览器和 Windows Defender SmartScreen「未知发布者」拦截，且缺少系统商店渠道与自动更新能力。
- **核心目标**：
  1. 建立 **双轨构建机制**（如 `-PstoreEdition=true`）：同一代码库分别输出「官网完整版 EXE」与「Microsoft Store 纯净版 x64 MSIX」。
  2. **商店托管分发**：打包为符合商店规范的 `.msix` 上传 Microsoft Partner Center，由微软官方免费代签、分发与自动更新，免除商业代码签名证书费用。
  3. **合规空壳改造**：商店版在打包时剔除 34 个内置漫画源脚本与高风险 R18 预设，仅保留本地漫画、自建服务与用户手动导入源脚本的能力；保留图库模块但出厂默认锁定全年龄过滤与封面打码遮罩。
  4. **容器沙盒适配**：兼容 MSIX 应用容器隔离目录，在清单中静态声明协议与能力，并跳过容器运行态的动态导 `.reg` 注册表操作。
  5. **开源与市场范围**：遵循 GPL-3.0 免费上架，面向全球市场（含中国大陆区）发布。
- **非目标（Non-Goals）**：
  - **本期不做传统 EXE/MSI 外链模式（Store Win32 App）**：该模式虽可免改沙盒，但微软不提供代签，必须自费购买商业代码签名证书并自行托管公网高可用下载直链，不适合当前免费开源节奏。
  - **本期不做商店版与官网 EXE 版共享同一真实 `%LOCALAPPDATA%\venera` 目录**：强行绕开 MSIX 容器隔离易触发权限与双装数据库锁死/协议冲突问题，且违背商店清洁卸载规范；改由引导老用户使用 `.venera` 备份迁移。
  - **本期不制作 ARM64 商店包**：现有桥接依赖 `li.songe.webview2:webview2-compose` 当前明确面向 Windows x64，首版仅发布 x64 包体。
  - **本期不内置 VLC 运行时**：图库视频播放能力仍依赖用户本机安装的 VLC，在商店介绍中说明为可选外部依赖，避免包体膨胀与第三方许可耦合。

## 2. 用户操作流

1. **账号与前置准备（开发者侧，可先行推进）**：
   - 注册并核验 Microsoft Partner Center 个人开发者账号（准备个人实名证件与支持邮箱）。
   - 占坑应用名称（首选 `VComic`，若已被占用则用 `VComic Reader`），获取后台分配的 `Identity Name`、`Publisher`（`CN=...`）与 `PublisherDisplayName`。
   - 在项目宣传站点（GitHub Pages）补齐公开的静态隐私政策页（说明纯本地运行、不采集上传隐私、第三方导入脚本与网络请求由用户自负合规责任）。
   - 准备不含任何第三方版权漫画或敏感图库画面的商店截图（聚焦本地阅读器、阅读统计、浅深色主题界面）。
2. **获取与安装（用户侧）**：
   - 在 Microsoft Store 搜索并点击「获取」，由微软商店完成下载、官方数字签名校验与无弹窗安装。
3. **运行与迁移（用户侧）**：
   - 首次打开即进入无内置漫画源的纯净阅读器界面，可浏览本地漫画/接入自建库，或自行导入外部源脚本；图库默认处于全年龄与打码保护状态。
   - 若用户此前用过官网 EXE 版，可通过设置页的 `.venera` 整包备份导出再导入商店版完成数据迁移；在浏览器进行 Pixiv 登录授权后，通过清单静态声明的 `pixiv://` 协议自动回调回应用。
4. **卸载（用户侧）**：
   - 通过开始菜单或系统应用列表卸载，MSIX 容器隔离数据随应用一并清理，系统无注册表或快捷方式残留。

## 3. 范围

- **涉及屏与模块**：
  - 构建配置：`desktop/build.gradle.kts`（新增 `-PstoreEdition=true` 开关、MSIX 图标资源裁切任务、清单生成与 `makeappx.exe` 打包任务；发布前对齐 `desktopPackageVersion` 与文档口径）。
  - 资源与源加载：打包时过滤 `src/main/resources/sources/*.js` 及敏感预设；引擎加载空源目录时保证界面与空态引导正常不崩溃。
  - 图库与内容保护：商店版出厂默认值锁定全年龄分级与封面打码遮罩。
  - 平台协议注册：`platform/DesktopProtocolRegistrar.kt` 增加 MSIX 包身份运行态检测（命中包身份即跳过生成并导入 `venera-protocols.reg`）。
  - 商店清单与图标资源：`desktop/packaging/` 新增 `AppxManifest.xml` 模板与多尺寸 PNG 磁贴图标（由 `vcomic_icon.png` 生成），声明 `runFullTrust`、`internetClient` 能力及 `pixiv` / `venera` 自定义协议。
- **涉及表与列（含迁移版本号）**：无数据库表结构变化。
- **涉及启动参数或构建项**：
  - 新增 Gradle 属性 `-PstoreEdition=true`（控制纯净版裁剪与清单开关，默认 `false` 保持现有官网安装版行为不变）。
  - 新增 Gradle 打包任务（如 `:desktop:packageMsix`，具体命名在立项实现时确定）。

## 4. 边界与异常

- **空态（无任何内置漫画源）**：商店版初次启动时源清单为空，搜索/探索/书架应清晰引导用户导入本地漫画或添加源脚本，不得因无默认启用源 `baozi`/`copy_manga`/`jm`/`manga_dex` 而抛异常或白屏。
- **网络与地域边界（中国大陆区与外网图库）**：用户未配置代理导致图库或外网站点无法直连时，保留清晰的网络失败提示与代理入口；商店页描述需明确软件定位为「本地/自建阅读器」及在线图库依赖网络环境，降低裸连差评风险。
- **审核驳回风险与退路（重要）**：尽管商店版隐藏或默认屏蔽 R18 内容，但保留完整图库入口仍存在较高概率被微软人工审核（尤其中国大陆区）以「包含未授权第三方站点或可切入成人内容」驳回。届时可低成本收紧 `-PstoreEdition=true` 开关，在商店版中进一步裁除高风险图站入口并重提。
- **协议冲突（双版共存）**：若同一台机器同时安装了官网 EXE 版与商店 MSIX 版，两者均注册 `pixiv://` 与 `venera://` 协议，Windows 将提示选择打开方式或在设置中指定默认应用；文档与设置页中标注二者数据与协议独立。
- **缺失 VLC 运行时**：图库视频播放失败时维持现有「提示未安装 VLC」逻辑，不伪装支持。
- **MSIX 提交规范**：上传到 Partner Center 的 `.msix` 必须为**未签名**包体（由微软后台统一代签）；本地测试时需另用自签测试证书签名并提前导入本机受信任根证书后安装。

## 5. 验收

- **判据（计划补充或复核）**：
  - 发布前须确保 `:desktop:test` 全量测试基线恢复全绿（清零既有红灯）。
  - 补充针对商店版配置的单测：验证 `storeEdition=true` 时内置敏感源被过滤、容器包身份识别逻辑可正确跳过 `.reg` 注册、商店版默认内容分级为全年龄与开启封面打码。
- **端到端验证（本地自签包 + WACK 预检）**：
  - 使用自签测试证书安装生成的 `.msix` 包，在 Windows 真机完成：安装 → 无黑框启动 → 本地漫画阅读 → 导入外部脚本 → `.venera` 备份导入 → 图库默认遮罩确认 → `pixiv://` 回调测试 → 卸载清盘校验。
  - 运行微软官方 Windows App Certification Kit（WACK）验证本地包体全部合规项通过。
- **取证读数**：
  - 编译与单测日志（含商店版与普通版双轨打包退出码及产物大小检查）。
  - 应用数据根运行日志确认容器运行态成功跳过 `.reg` 写入并保持正常运行。
