# 关注动态 · 双源重做稿（v2）

> 定位：把 pixiv 关注与图库关注收进同一屏，但**不共用一条时间轴**。
> 视觉实体：`mockup.html`（四屏：全部 / 图库单源 / 画师视图 / 状态与对照）。

## 0. 与旧稿的关系

- `artist-inbox-2026-11-17/`（v1）假设五分段、星标、暂缓、`last_read_timestamp` 与"按发布时间精确排序"，这些在当前代码里都不成立，且色板与 `DesktopTheme` 不一致。不覆盖，只替换其结构假设。
- 本稿在首版单源稿基础上扩成双源：pixiv 与图库各成一流，来源轴可切换，**不做跨源混排**。

## 1. 能力边界

### 1.1 pixiv

| 能力 | 现状与出处 | 稿中处理 |
|---|---|---|
| 新作流 | `followIllustFeed(bearer, restrict, nextUrl, fresh)`，可翻页 | 单源时间视图的数据源 |
| 发布时间 | 行模型**没有**该字段；`create_date` 解析后只落在详情模型（`PixivAppParse.kt:475`） | 卡片不印时间；排序用站方默认序 |
| 每画师作品 | `userIllusts(bearer, userId, type, nextUrl, fresh)` | P1 增量兜底 |
| 关注名单 | 桌面侧纯本地；`DesktopGalleryArtistFollows` 注释说明桌面无 pixiv 腿 | 图库/ pisiv 各自一张名单，不互相写 |
| 页数 | `GalleryPost.pageCount` 有值 | 卡片右上页数标 |

### 1.2 图库

| 能力 | 现状与出处 | 稿中处理 |
|---|---|---|
| 关注名单 | `GalleryArtistFollow(site, name, addedAt)`，键 `routeKey:name`，纯本地（`GalleryArtistFollows.kt:16`） | 图库单源的输入 |
| 新作取数 | `tags=` + `limit` + `page/pid`（`YandeReClient.kt:114`、`GelbooruClient.kt:168`、`SafebooruClient.kt:113`） | 每标签拉第一页，追加去重 |
| 发布时间 | Gelbooru 给 `created_at`（`GelbooruWindowBoundary.kt:24`），yande.re 同族 | 图库单源可按真实时间放分界线 |
| 水位 | 自增 post id；已有 `id:>=M sort:id:asc&limit=1` 边界工具 | 用 `maxPostId` 判"新入库"，比 pixiv 更可靠 |
| 站徽标 | `GallerySite.routeKey` 已是身份前缀 | 图库卡片**必显**来源站 |
| 页数 | booru 不给 `pageCount` | **不显示**页数标，不补 1 |
| 标题 | 站方不给标题；现有标题由标签推算（`GalleryCardTitle`） | 图库卡首行是推算标题，不是原题 |
| 画师头像 | 站方无；`artist.json` 只部分给 urls | 首字母座；有缓存则用缓存 |
| 标签上限 | Safebooru 匿名 `tags=` 最多 2 段（`GallerySearch.kt:131`） | 该站不加 `order:` 等附加参数，只吃默认序 |

## 2. 信息架构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 56：← 关注动态 [未读 20 项]         [时间|画师] 刷新 ⋯    │
├──────────────────────────────────────────────────────────────┤
│ 副栏 48：[全部|图库|pixiv] · 14:20 同步          全部已读      │
├──────────────────────────────────────────────────────────────┤
│ 内容：分区流（全部） / 单源 4 列墙（图库、pixiv） / 画师行     │
└──────────────────────────────────────────────────────────────┘
```

| 区域 | 尺寸 | 说明 |
|---|---|---|
| 顶栏 | 高 56，左右 18/14 | 只放形式切换（时间/画师）与刷新 |
| 副栏 | 高 48，左右 22 | 来源轴 + 同步状态 + 全局已读 |
| 内容 | 左右 24，列距 16 | 4 列，单卡 336 |
| 分区头 | 跨 4 列，高 32 | 段名 + 计数 + 段内"全部已读" |
| 分界线 | 跨 4 列，高 44 | 单源视图各有一条；全部视图每段各一条 |

## 3. 视图规格

### 3.1 全部（默认）

- 结构：两段堆叠，`图库` 在前、`pixiv` 在后，各带分区头，各自排序、各自分界线。
- **不混排**：pixiv 行没有发布时间，与 booru 的 `created_at` 不可比；混成一条轴就是假排序。
- 计数分开表述：图库用「张」，pixiv 用「篇」，顶栏合计用「项」。
- 段落内滚动连续；段与段之间不留大空隙，靠分区头分隔。

### 3.2 图库单源

- 顺序：`created_at` 降序（站方默认序即此口径）。
- 分界线：`lastViewedAt` 之上为新入库区，之下为历史区。
- 卡片：首行推算标题、次行画师 + 站徽标；**无页数标**。
- 新语义：标题为「新入库」，不写「刚发布」——转载、重传、合集都会进这一流。

### 3.3 pixiv 单源

- 顺序：站方默认序；卡片首行原题、次行画师；右上页数标。
- 分界线：按 `lastViewedAt` 定位；因行无时间戳，**分界线标签不带日期**，只写「上次查看」。
- 若 P1 补上 `publishAt`，此条升级为与图库同形的日期标签。

### 3.4 画师视图

- 同一屏两源混排**行**（不是把作品混排）：图库行在前、pixiv 行在后，或按最近更新交替，排序键统一为「组内最新作品的入库时刻」。
- 图库行：首字母座 + 名字 + 站徽标 + 「N 张未读」+ 4 张缩略 + 余量块。
- pixiv 行：真头像 + 名字 + 「N 篇未读」+ 4 张缩略 + 余量块。
- 图库行点击 = 按该标签搜全部来源（沿用 `GalleryFollowedArtists` 的显示层合并口径）。

### 3.5 状态

| 状态 | 主标题 | 副标题 |
|---|---|---|
| 首轮索引 | 正在建立索引 | 首次同步需要一点时间 |
| 空 | 暂无新作品 | 关注画师最近没有更新 |
| 图库限流 | 图库限流 | 稍后自动重试 |
| 网络失败 | 同步失败 | 请检查网络后重试 |

## 4. 状态模型

两源各自一套水位，作品键统一为 `(site, id)`：

| 源 | 水位 | 新判定 |
|---|---|---|
| pixiv | 每画师 `maxIllustId` | `id > 水位` |
| 图库 | 每标签 `maxPostId` + `created_at` | `id > 水位`；入库时间用于分界线 |
| 已读 | `work.readAt` | 打开作品即写 |
| 分界 | `lastViewedAt`（全局一个） | 单源视图用来分区 |

- 已读不写水位；「全部已读」只作用于当前未读集合。
- 图库限流退避：1 / 5 / 15 / 60 分钟，屏上给「稍后自动重试」，不反复打。
- 关注名单两张：pixiv uid、图库 `site+tag`。**不合并存储**，只在画师视图的显示层合并同名。

## 6. 移除项

| 移除 | 理由 |
|---|---|
| 跨源统一时间轴 | pixiv 无发布时间，混排即假排序 |
| 图库页数标 | 站方不给，补 1 就是编 |
| 图库头像 | 站方不提供，首字母座即可 |
| 「刚发布」话术 | 图库是新入库，含转载与重传 |
| 五分段 / 星标 / 暂缓 | 粒度与键都不可靠 |
| 「新增 30 部」 | 页长冒充增量 |
| 统一量词 | 张 / 篇 / 项 各按源用对 |

## 8. 落实顺序与验收

- P0：来源轴 + 图库单源（每标签首屏 `limit=20`，`maxPostId` 判新），pixiv 保持现状。
- P1：图库接 `created_at` 放分界线；pixiv 补 `publishAt`；全部视图两段分区。
- P2：分批轮转、限流退避、Safebooru 特例、tag type 过滤（过滤后图库才配叫「画师」）。

验收：全部视图两段各自只出现一条分界线；图库卡无页数标、必有站徽标；pixiv 卡有页数标、无站徽标；量词按源正确；限流态不反复重试。
