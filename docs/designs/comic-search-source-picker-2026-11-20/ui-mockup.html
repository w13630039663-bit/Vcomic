落地要点

实施说明

视觉

  • 源按钮 36 高、9 圆角、20 图标 + 13/600 站名 + 折叠箭头；打开态描边走 accent。
  • 清单 308 宽、12 圆角、行高 36、图标 22；分组标题 10.5 / 字距 0.08em，色 ink-3。
  • 选中行：accent-soft 底 + 右侧对勾；悬停行 rgba 白 6%（浅色 4.5% 黑）。
  • 无图标源退化成首字字块（与站点墙同法），不引新占位图。

交互

  • 点源按钮开合；点面板外、Esc 关闭；打开即聚焦搜索框。
  • ↑↓ 移动高亮、Enter 确认；过滤按站名与源键双匹配。
  • 点行 = 换源 + 关闭 + 复用现有换源管线（清结果、重置筛选、原词重搜）。
  • 换源后焦点回检索场，不落在已消失的清单上。

数据

  • 清单来源不变：源管理开启账（enabled 过滤、原序），组件只加展示层。
  • 图标读 DesktopSourceIcons.bytesOf(key)，与源管理墙同源，不另存一份。
  • 「最近使用」新增一条本地记录（最多 5 条，换源时写入）；首次无记录时整组不摆。
  • 搜索管线、筛选组读取、历史、速览、分页一律不动。

改动面

  • 新增：源选择器组件（按钮 + 清单），放 desktop/.../search/ 与现有屏同包。
  • 改：DesktopSearchScreen 取新形参、删「来源」行；DesktopDiscoverScreen 透传。
  • 改：壳 VeneraDesktopLargeScreen 一处组装（源按钮所需图标字节与最近账）。
  • 判据：DesktopSearchSourceEntryTest 等点名用例同步改期望。

风险：壳的大 lambda 捕获槽已近上限（255 槽坑），新组件整颗抽成顶层纯件、状态尽量下沉到组件内部，壳只多传一份数据。
